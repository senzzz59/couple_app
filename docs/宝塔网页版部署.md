# couple.senfoundry.com 网页版部署

当前使用 GitHub master webhook 同时更新独立的 frontend / backend；从 Gitee 迁移的已有服务器还需按 [自动部署说明](../deploy/README.md) 切换仓库地址和接收器。以下为手动上传部署的备选方法，不代表仓库已生成压缩包。

现在优先使用网页版。iPhone / 安卓打开同一个 HTTPS 链接即可登录；添加到主屏幕后像 App 一样打开，不需要 EAS、签名或 TestFlight。

## 部署包

- `artifacts/couple-web.zip`：网页文件。解压后 `index.html`、`sw.js`、`version.json` 应直接位于网站根目录。
- `artifacts/couple-server.zip`：后端源代码和 Docker 配置。解压到网站目录外，例如 `/www/couple-app/server`，不能放到可公开访问的网站根目录。
- `deploy/baota-nginx.conf`：宝塔 Nginx 站点内的配置片段。

包中不包含现有用户数据、照片或 `.env`。更新现有后端时保留服务器上的 `.env`、`data/` 和 `uploads/`。

## 1. 域名和 HTTPS

将 `couple.senfoundry.com` 的 DNS 指向服务器。在宝塔「网站」添加此域名，类型选择静态 / PHP 项目均可，使用 Nginx，根目录设置为 `/www/wwwroot/couple.senfoundry.com`。

上传 `couple-web.zip` 并解压到根目录。申请并部署 SSL 证书，然后开启强制 HTTPS。主屏幕安装、Service Worker 和网页定位需要安全连接。

## 2. 后端（首次安装）

将 `couple-server.zip` 解压到 `/www/couple-app/server`。安装宝塔 Docker 管理工具后，在终端运行：

```sh
cd /www/couple-app/server
cp .env.example .env
# 在宝塔文件编辑器中修改 .env，再执行：
docker compose up -d --build
```

`.env` 至少填写：

- `DB_HOST=127.0.0.1`、`DB_PORT=3306`、`DB_NAME=couple`、`DB_USER=couple`、`DB_PASSWORD`：宝塔现有数据库连接配置，`DATABASE_URL` 留空。
- `JWT_SECRET`：随机长字符串，不能使用示例值。
- `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASS`、`SMTP_FROM`：真实邮箱服务配置，两人注册和找回密码会用到。

不使用 Docker 时，也可连接宝塔现有的 MySQL 5.7.44 / 8+ 数据库，安装 Node.js 24+，填写数据库配置，将 `npm start` 作为常驻 Node 项目运行。Nginx 仍代理到本机 `8787`。

生产 Docker 使用 Linux host 网络连接宝塔现有数据库，API 只监听 `127.0.0.1:8787`。后端启动时会执行已提交迁移；需要自动备份、检查迁移和更新前后端时，请使用 [自动部署说明](../deploy/README.md) 的脚本，而不是直接更新容器。

## 3. 连接网页与后端

宝塔站点「设置 → 配置文件」：保留现有域名和 SSL 配置，将 `deploy/baota-nginx.conf` 放进对应 `server {}` 内。原有 `location /` 需要替换，不能重复。

该配置把 `/api/` 和 `/files/` 转给后端，也支持双人实时同步的 WebSocket。动态店铺链接和直接刷新页面会回到前端路由。`sw.js`、`version.json`、`web-build.js` 不使用长期缓存，带哈希的资源可以长期缓存。

保存后检测配置并重载 Nginx。

## 4. 使用与验收

1. 打开 `https://couple.senfoundry.com/api/health`，应显示 `{"ok":true}`。
2. 打开 `https://couple.senfoundry.com`，分别注册两人的邮箱账号。
3. 测试上传照片、发动态、发表评论和完成清单，检查另一台手机是否同步。
4. iPhone 用 Safari 的分享菜单「添加到主屏幕」；安卓在浏览器菜单选择「安装应用」或「添加到主屏幕」。设置页有说明。
5. 直接打开 `/settings` 和店铺链接，再刷新，确认不是 404。

当前浏览器检查使用模拟账号和接口，验证了手机界面、同域名请求、主屏幕说明、版本检查和离线提示；真实数据库、SMTP 和两人联机仍需在服务器上线后验收。

## 以后更新

在开发电脑的 `frontend` 目录运行 `npm run build:web`，上传新的 `dist` 文件。先上传新资源、图标、离线页等文件，最后上传 HTML、`web-build.js`、`sw.js`、`version.json`，减少更新过程中不完整资源的风险。

首次更新不要立即删除旧的带哈希资源，保留一段时间供仍打开旧页面的手机使用。网页每次打开都重新获取 HTML；使用过程中的更新会提示到「我的」刷新，不会强行重载正在编辑的内容。不再需要原生 App 的 EAS 更新流程。

如果后端也有修改，更新后端源代码并运行 `docker compose up -d --build`。保留数据目录和配置。

## 提醒与离线范围

网页内可以查看纪念日和清单，打开页面时支持实时戳一戳。关闭网页后的系统提醒和离线推送暂未接入。

Service Worker 仅缓存公开的网页代码、字体、图标和离线提示，不缓存 `/api/` 的私人数据、`/files/` 照片或带登录头的请求。断网时展示提示；不支持离线编辑和数据同步。
