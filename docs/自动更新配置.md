# App 在线更新

当前已改为优先使用网页版，网页更新不需要 EAS。请使用 [宝塔网页版部署](宝塔网页版部署.md) 中的更新方法。下面保留的是原生安装包的配置流程。

## 手机上的行为

- 启动时自动检查兼容更新。如果检查和下载在 8 秒内完成，App 会在展示页面前自动重启并使用新版本。
- 网络较慢时，8 秒后照常进入 App。后台下载完成的版本在下一次启动时生效。
- 回到前台时也会检查，自动检查间隔至少 15 分钟；使用过程中的下载不会强行重启正在填写的表单。
- 设置页的“检查更新”可以立即检查、下载并重启安装。检查或下载期间可以点“先继续使用”，让下载在后台继续。
- 断网、下载失败时继续使用当前版本；手动检查可重试。支持更新服务下发的回滚指令，保留 Expo 的内置故障恢复保护。
- 设置页显示安装包版本与当前更新编号。没有配置更新服务、开发模式、Expo Go 和网页预览不会调用正式更新接口。

## 首次开通（需要做一次）

当前仓库还没有实际 EAS 项目 ID，自动更新服务默认关闭，不能把示例 ID 用于发布。

1. 在 Expo / EAS 中创建或选择自己的 `us-couple` 项目，记录项目 UUID。可以在 `frontend` 中运行 `npx eas-cli@latest login`、`npx eas-cli@latest init`；动态配置文件无法自动写入时，用下一步脚本保存 ID。
2. 在 `frontend` 中运行 `npm run updates:configure -- 你的真实项目UUID`。它只将项目 ID 保存到 `app.json`，`app.config.ts` 自动生成 EAS 更新地址。也支持通过 `EXPO_PUBLIC_EAS_PROJECT_ID` 提供 ID；若两者都设置，环境变量优先，务必保持一致。
3. 为 EAS 的 `preview` / `production` 环境配置 App 用到的 `EXPO_PUBLIC_API_URL`、地图 Key 等环境变量。首次打包和以后发布更新必须使用相同环境，避免更新把服务器地址或地图配置清空。可以在 EAS 控制台中配置，项目 ID已经持久保存时无需额外设置该环境变量。
4. 重新打包并在两台手机安装一次：测试版用 `npx eas-cli@latest build --profile preview --platform android`，正式版用 `npx eas-cli@latest build --profile production --platform all`。iOS 仍需要对应的签名和分发方式。旧安装包没有更新模块和更新地址，无法靠一次在线更新补上这项能力。

`eas.json` 已将 preview 和 production 分别绑定到对应更新频道和环境。运行时采用 fingerprint 策略，阻止手机加载与当前原生代码不兼容的更新。

## 以后发布更新

先在 `frontend` 运行 `npm run lint` 和 `npx tsc --noEmit`，在 `backend` 运行 `npm test`。

```powershell
# 先发布到测试频道，验证真实手机的下载和重启
npm run update:preview -- --message "修复动态和提醒"

# 验证后发布给正式安装包
npm run update:production -- --message "修复动态和提醒"
```

首次开通时无需再执行 `eas update:configure`；本项目的动态配置已经提供更新地址、runtimeVersion 和检查策略。请保留 `checkAutomatically: NEVER`，检查与安装由 App 控制，以避免两套流程同时请求更新。

## 能更新哪些内容

界面、业务逻辑和资源等与安装包运行时兼容的修改，可以在线更新。新增原生模块、系统权限、SDK 升级或其他导致 fingerprint 改变的修改，需要发布新的安装包并重新安装。在线更新不会更新后端服务，也不会静默安装新的 APK / IPA。

## 真机验收

1. 安装绑定 preview 频道的测试包，打开设置页，确认当前版本和更新编号。
2. 修改一个可见文案并发布 preview 更新。重启 App，确认启动检查下载后生效。
3. 断网启动，应在最多 8 秒后可正常使用；联网后手动检查应成功。
4. 新增动态的表单中暂不保存，切换后台再回到 App。更新只能后台下载，不能强行重启丢失输入。
5. 在设置页手动检查，测试取消等待、重复点击、下载失败重试及安装后的版本变化。
